# 오브온 운영 관리자

기존 `users.role = admin` 계정으로 로그인한 뒤 `/admin`에 접속합니다. 계정 권한은 변경하지 않았습니다.

- 대시보드: 실제 등록 상품 수, 주문 수, 결제 매출, 배송 준비 건수, 한국 시간 기준 최근 7일 매출. 취소·환불 주문은 매출 집계에서 제외합니다.
- 상품: 20개 단위 목록, 매장·검색어 필터, 등록/수정, 가격·할인가·판매 상태·카테고리·브랜드·설명·옵션·이미지 관리. 삭제 대신 숨김을 사용할 수 있습니다.
- 검색 태그: `#롱 스커트 #맥시` 또는 쉼표로 입력하고 Enter로 확정합니다. 고객은 `롱 스커트`, `#롱 #스커트`, `롱 치마` 등으로 찾을 수 있습니다. 단어들을 AND 조건으로 검색하고, 합친 표현도 함께 찾습니다.
- 로고·배너: 의류/뷰티/홈 각각 로고와 배너 10개 슬롯을 관리합니다. 제목·보조 문구·이미지·노출·순서·카테고리·검색어를 설정하며, 고객은 배너 어디를 눌러도 해당 상품 목록으로 이동합니다. URL 조건은 새로고침과 뒤로가기에서도 유지합니다.
- 이미지: JPG/PNG/WebP, 파일당 최대 5MB. 브라우저에서 긴 변 최대 1920px WebP로 변환해 `store-assets`에 저장합니다. 쓰기는 관리자만 허용합니다.
- 주문·배송: 수령인/주문번호·배송 상태 필터, 주문 상세·상품·배송지 확인, 배송사·송장·배송 상태 저장. 결제 완료 주문만 준비/배송/완료로 처리할 수 있습니다. 배송완료 되돌림과 동시 편집 덮어쓰기를 막습니다. 고객 주문 상세에도 배송 정보가 표시됩니다. 결제 취소/환불 API나 택배사 실시간 조회는 이 기능에 포함되지 않습니다.

## 데이터 추가

`scripts/data/oveon-additional-products.json`의 대표 이미지 205개를 정상 이미지 응답으로 확인한 뒤 추가했습니다.

- 한국 브랜드 의류 107개: 기존 한국 패션 데이터셋의 다른 상품. 출처와 라이선스는 `scripts/data/fashion-source.json` 참조.
- 스커트 18개: https://www.charmer.kr/category/스커트/55/ 의 실제 상품명·이미지·가격. 기존 모델과 중복되는 항목 및 깨진 이미지는 제외.
- 뷰티 40개: https://www.cosrx.com/products.json?limit=250 의 실제 상품. 사은품·유통기한 임박 상품은 제외하고 등록 구성은 원본 변형 상품명으로 기록.
- 가구 40개: https://fermliving.com/collections/furniture/products.json?limit=100 의 실제 상품. 원본 모델명과 구성은 추가 정보에 기록.

뷰티·가구의 원화 가격은 오브온 등록 판매가격이며 원본 해외 판매가나 실시간 환산가가 아닙니다. 상품 정보와 이미지의 출처는 각 상품의 추가 정보에도 기록합니다. 메타데이터 라이선스가 이미지 이용 권한을 뜻하지는 않습니다.

`npx tsx scripts/seed-additional-products.ts`는 고정 ID와 ON CONFLICT DO NOTHING으로 기존 상품 및 관리자가 수정한 내용을 보존합니다. 기존 리뷰·주문·계정은 유지하며, 새 리뷰·주문·매출은 생성하지 않습니다.

migration `0028_store_admin.sql`에 설정 테이블/RLS, 이미지 버킷/RLS, 주문 배송 필드·보호 트리거, 관리자 집계 RPC가 포함되어 있습니다.

추가 보호: `0029_guard_user_roles.sql`은 일반 회원이 자기 프로필의 role 값을 admin으로 바꾸는 것을 막습니다. 기존 관리자 1개는 유지했고, 실제 일반 회원 역할로 자기 승격과 이미지 업로드가 거부되는 것을 롤백 트랜잭션에서 확인했습니다.

## 판매 분석 대시보드

`/admin`은 **시뮬레이션 전용** 분석 화면입니다. `/admin/live`는 기존 실제 주문 대시보드이며 실제 주문·배송 관리는 `/admin/orders`에서 처리합니다.

- 매출 요약: 순매출, 직전 동기간 비교, 주문·판매 수량, 객단가, 할인·환불액, 취소율, 출고 대기.
- 상품별 판매: 순매출 TOP 50, 판매 수량·주문 수 및 상품 관리 연결.
- 배송·유입: 유입 경로, 배송 상태, 지역, 결제 수단, 시간대, 신규·재구매 주문 비중.
- 판매 내역: 25건씩 조회, 상태·날짜별 필터 및 주문별 금액·할인·유입·배송 상세 펼치기. 일별 차트에서도 날짜별 판매 내역으로 이동합니다.
- 최근 7/30/90일, 전체/의류/뷰티/홈 필터를 지원합니다. 날짜 경계는 Asia/Seoul 기준입니다.

`0030_sales_simulation.sql`의 `sales_simulations`는 실제 `orders`, `order_items`, `payments`, 고객 계정 및 재고와 분리됩니다. 관리자만 RLS로 읽을 수 있고 집계 RPC도 관리자 권한을 검사합니다. 가상 고객의 연락처 등 개인정보는 생성하지 않습니다. 한 판매 행은 한 상품의 1~3개 주문이며, 혼합 장바구니·부분 환불은 모델링하지 않습니다. 순매출은 할인 후 결제 완료 상품 금액이며 배송비는 포함하지 않습니다. 환불액은 해당 주문 생성 기간의 전액 환불액입니다.

```sh
node --import tsx scripts/seed-sales-simulation.ts
node --import tsx scripts/verify-sales-simulation.ts
```

시드는 실행일 기준 최근 180일의 하루 150~339건 슬롯을 생성합니다(당일은 현재 시각 이전만). 주말 가중치와 지역·시간대·유입·결제 수단 분포는 화면 확인을 위한 임의 설정이며 실제 시장 통계가 아닙니다. 재실행은 결정적 `SIM-날짜-번호` 키로 기존 시뮬레이션 행을 갱신하며 실제 주문을 변경하지 않습니다. 자동으로 매일 생성되는 기능은 없으므로 필요할 때 시드를 다시 실행합니다.
